# H-2 网络同步重构设计

**日期:** 2026-08-20
**状态:** Approved
**方式:** 服务端权威推送 + 按维度同步（简化版，不含区块范围扫描）

## 问题背景

当前服务器登录时会把所有维度的全部锚点（包括未激活口袋锚点）发送给客户端，导致口袋锚点坐标泄露。本次重构目标是：

- 口袋锚点只同步已激活的；
- 普通锚点按当前维度全量同步；
- 客户端不再长期持有其他维度的完整锚点数据。

## 需求确认

1. 玩家进入服务器时，同步当前维度的锚点数据；跨维度时再同步对应维度数据。
2. 口袋锚点：只同步玩家已激活的。
3. 普通传送锚点：不做激活过滤，按当前维度全量同步。
4. 已激活锚点的名字/UID 跨维度保留（用于传送列表）。
5. 已激活口袋锚点的位置只按当前维度同步。

## 数据模型

客户端维护：

| 数据 | 内容 | 范围 |
|---|---|---|
| `activated` | 已激活锚点轻量元数据：UID / 类型 / 名称 | 跨所有维度 |
| `waypoints` | 锚点完整数据：UID / 维度 / 坐标 / 类型 / 名称 | 仅当前维度 |

`waypoints` 包含：
- 当前维度所有普通传送锚点；
- 当前维度已激活口袋传送锚点。

不包含：
- 其他维度普通锚点；
- 未激活口袋锚点；
- 其他维度已激活口袋锚点位置。

## 同步流程

### 玩家进入服务器

1. `SyncActivatedWaypointsPayload`：所有已激活锚点元数据。
2. `SyncDimensionWaypointsPayload`：当前维度所有普通锚点 + 当前维度已激活口袋锚点完整数据。

客户端：
- 用第 1 个包设置 `activated`；
- 用第 2 个包替换当前维度的 `waypoints`。

### 玩家跨维度

- 服务端发送新维度的 `SyncDimensionWaypointsPayload`。
- 客户端清空旧维度完整数据，载入新维度完整数据；
- `activated` 保持不变。

### 激活锚点

- 服务端加入 `activated`，发送 `ActivatedWaypointAddPayload`（元数据）。
- 若该锚点位于玩家当前维度且尚未在 `waypoints` 中，则发送 `AddWaypointPayload` 完整数据。
- 普通锚点已在当前维度全量数据中时，只更新激活状态即可。

### 取消激活

- 服务端从 `activated` 移除，发送 `ActivatedWaypointRemovePayload`。
- 口袋锚点且位于当前维度：发送 `RemoveWaypointPayload` 从完整数据移除。
- 普通锚点：保留在 `waypoints` 中（仍作为未激活普通锚点显示）。

### 锚点新增 / 改名 / 删除

| 锚点类型 | 完整数据广播范围 | 元数据广播范围 |
|---|---|---|
| 普通锚点 | 仅当前处于该维度的玩家 | 无需元数据 |
| 口袋锚点 | 已激活该锚点且当前处于该维度的玩家 | 已激活该锚点的所有玩家 |

## Xaero 集成影响

- 小地图：使用当前维度完整数据，天然符合维度隔离。
- 世界地图：
  - 当前维度正常显示；
  - 其他维度不显示锚点（行为变化，符合设计）。
- 传送列表 GUI：使用跨维度 `activated` 元数据，仍可显示所有已激活锚点并跨维度传送。

## 边界情况

- 跨维度瞬间：以最后一次快照为准。
- 在其他维度激活口袋锚点：客户端只收到元数据；进入该维度后快照带上它。
- 在其他维度取消激活口袋锚点：客户端只移除元数据；之后进入该维度不再收到它。
- 普通锚点改名/删除：只通知当前处于该维度的玩家。

## 非目标

- 不做客户端持久化缓存。
- 不做区块范围扫描。
- 不做未激活普通锚点的按需加载。
- 不改变服务端权威传送校验。
