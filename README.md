# Teleport Waypoint（传送锚点）

一个 Minecraft **1.21.1 NeoForge** 模组：在世界上放置锚点，右键激活后，即可在任意已激活的锚点之间传送，支持跨维度。

- **Mod ID：** `teleportwaypoint`
- **版本：** `0.4.0`
- **加载器：** NeoForge `21.1.236+`
- **游戏版本：** Minecraft `1.21.1`
- **许可：** MIT

---

## 已实现功能

- 两种锚点方块：不可破坏的**传送锚点**与可破坏的**口袋锚点**
- 右键激活锚点，激活状态按玩家独立保存
- 在任意两个已激活锚点之间传送（**支持跨维度**），自动选择落点并带传送音效/粒子
- 服务端严格校验传送请求，防止伪造与作弊
- 完整的传送列表 GUI：传送、删除、搜索、排序
- 改名界面：口袋锚点自由命名，普通锚点使用 ID（翻译键）命名
- 删除确认弹窗（只取消激活，不破坏方块）
- 按维度同步锚点数据：普通锚点全量同步当前维度，口袋锚点仅同步已激活的
- 已激活锚点元数据跨维度保留，用于传送列表
- 传送锚点与口袋锚点均支持含水
- **区块补锚**：新区块首次生成时自动在结构内补放传送锚点，由数据包标签黑白名单筛选（见下文）
- 内置原版结构与 YUNG 结构兼容数据包（自 0.4.0 起默认关闭，供旧存档过渡使用）
- 完整的中文（简体）与英文语言文件
- 自定义创造模式标签页，包含全部锚点物品
- **传送锚点动态渲染**：四颗柱顶水晶悬浮错相浮动、晶核自转、能量环反向旋转并浮动、核心光球呼吸脉冲（BER 实现，自发光）
- **状态外观**（per-player）：传送锚点未解锁红色/解锁青色；口袋锚点未解锁黄色/解锁淡绿色
- **物品 3D 展示**：物品栏与手持显示方块完整模型（传送锚点青色 / 口袋锚点绿色）
- **交互优化**：右键未解锁锚点仅激活（提示 + 经验球音效），不弹 GUI；已解锁后右键才打开传送列表
- NeoForge 配置界面入口：分通用 / Xaero 小地图 / Xaero 世界地图三组配置
- **Xaero 地图联动**：小地图与世界地图显示锚点，并严格按当前维度隔离

## 快速上手

### 1. 获取锚点

| 方块 | 获取方式 |
|------|----------|
| 传送锚点（Waypoint） | 创造模式物品栏；试炼密室等结构自然生成（可破坏，无掉落） |
| 口袋锚点（Pocket Waypoint） | 合成配方（回响碎片 + 末影珍珠 + 末地水晶）；创造模式物品栏 |

### 2. 放置与首次命名

- 放下锚点后会自动激活，并弹出命名界面：
  - **传送锚点**：只能填写小写字母、数字、下划线和点（`[a-z0-9_]+(\.[a-z0-9_]+)*`），用于组成翻译键名称；
  - **口袋锚点**：可填写任意名称（最长 64 个字符），空名称会回退为 `Pocket Waypoint`。
- 按 `Enter` 保存，`Esc` 关闭。

### 3. 激活锚点

- 右键点击未激活的锚点 → 自动激活（提示 + 音效），不打开传送列表；再次右键已激活的锚点才打开传送列表。
- 激活状态对每名玩家独立保存，并写入世界存档。

### 4. 传送

1. 右键点击任意已激活的锚点，打开**传送列表**；
2. 列表中会显示你已激活的全部锚点；
3. 点击目标锚点的按钮即可传送，落点会自动选在锚点旁可站立的位置。

> 传送校验：源锚点与目标锚点都必须是你已激活的，且你需要站在源锚点 **8 格以内**。

### 5. 改名

- **潜行 + 右键**锚点可直接打开改名界面；
- 或者在传送列表中**点击标题栏上的锚点名称（带 ✎ 图标）**进行改名。

### 6. 删除激活

- 传送列表中每项右侧的 **✕** 按钮用于删除该锚点的激活记录；
- 会先弹出确认窗口——**只会从你的列表移除，不会破坏锚点方块本身**；
- 若删除的是你当前正在使用的锚点，整个界面会自动关闭。

## 两种锚点对比

| | 传送锚点 `waypoint` | 口袋锚点 `pocket_waypoint` |
|---|---|---|
| 硬度 / 抗爆 | 黑曜石硬度/抗爆（`50` / `1200`） | 石头硬度/黑曜石抗爆（`1.5` / `1200`） |
| 命名方式 | ID + 翻译键（如“村庄”“试炼密室”） | 自由文本名称 |
| 所有者 | 无 | 绑定放置者 UUID |
| 改名权限 | 仅创造模式玩家 | 仅所有者（创造模式玩家可改任意口袋锚点） |
| 主要来源 | 结构生成 / 创造模式 | 合成配方 / 创造模式 |
| 破坏掉落 | 无掉落 | 掉落自身（不保留锚点数据，属设计行为） |

## 区块补锚（结构自动生成锚点）

### 机制

新区块**首次生成**并正式启用时，模组会检查该区块含哪些结构。若结构通过名单筛选，就按一套确定性规则在**该区块自身范围内**补放一个传送锚点。放置后完全复用既有的登记、同步、渲染与地图链路。

落点规则：**两层候选**，结构内（L1）优先，全败则退到整个区块（L2）；每层内跑两遍——第 1 遍要求「上方 8 格内有实心顶」（偏好落在室内），第 2 遍不加此条件（露天结构也能放置）。**允许放在水里**（锚点方块支持含水），**岩浆一律排除**。

> **触发只有「首次生成」这一个门。** 因此：存量存档不会被补放、玩家拆掉锚点后不会重生、模组也不需要任何去重存档文件。

### 两套名单：数据包标签

名单**不是配置项，而是本模组提供的两个数据包标签**：

| 标签 | 内容 | 对应模式 |
|---|---|---|
| `teleportwaypoint:waypoint_whitelist` | 12 个已适配结构 | `WHITELIST`（默认） |
| `teleportwaypoint:waypoint_blacklist` | 22 个未适配结构（压成 9 条） | `BLACKLIST` |

文件位于 `data/teleportwaypoint/tags/worldgen/structure/`，两者都是 `"replace": false`，因此**其他数据包与整合包可以追加条目而不覆盖本模组的文件**。

配置项只决定用哪张名单：

```toml
[structureWaypoints]
    # "WHITELIST" = only place in structures listed by teleportwaypoint:waypoint_whitelist
    # "BLACKLIST" = place in every structure EXCEPT those listed by teleportwaypoint:waypoint_blacklist
    mode = "WHITELIST"
    debugMode = false
```

**「标签缺失」与「标签为空」是两件不同的事：**

| 情况 | 行为 | 日志 |
|---|---|---|
| 标签**不存在**（数据包被禁用／文件缺失） | 白名单 ⇒ 一个都不放；黑名单 ⇒ 全部放 | WARN 一次 |
| 标签**存在但为空**（`"values": []`） | 同上 | **不记日志**（这是合法配置） |

### 为新结构接入（整合包作者）

三步，全部在数据包侧，**不需要改本模组任何文件**：

**第 1 步：确认结构的注册表 ID。** 查看该模组 jar 内 `data/<ns>/worldgen/structure/*.json` 的文件名。

**第 2 步：在自己的数据包里追加白名单条目。** 新建同名标签文件，注意 `"replace": false`：

```json
{
  "replace": false,
  "values": [
    { "id": "betterwitchhuts:witch_hut", "required": false }
  ]
}
```

`"required": false` 表示「该模组没装就跳过这一条」。**可以预先写进去，等模组装上就自动生效。**

**第 3 步：补翻译键（可选）。** 键名是 `tpwp.<namespace>.<path>`，例如 `tpwp.betterwitchhuts.witch_hut`。不补也不会出问题，会回退到由 id 人工化得到的名称（如 `Betterwitchhuts Witch Hut`）。

### 从 0.3.0 升级

1. **两个内置数据包现在默认关闭**（`defaultEnableStructureWaypoints`、`defaultEnableYungStructureWaypoints` 默认值改为 `false`）。这只对**新世界**生效。
2. **既有存档必须手动关闭**这两个数据包——改默认值**不会**自动关掉已经启用的包。否则升级后新生成的区块里会出现**两个锚点**（旧数据包一个 + 新区块补锚一个）。
3. 旧存档中已有锚点的名称**不受影响**：旧的 `teleportwaypoint.waypoint.*` 翻译键全部保留为别名。
4. 旧存档**不会被补锚**，这是设计意图：补锚只发生在区块首次生成时。

## 权限规则

| 操作 | 传送锚点 | 口袋锚点 |
|------|----------|----------|
| 激活 / 传送 | 任意玩家 | 任意玩家 |
| 改名 | 创造模式玩家 | 所有者；创造模式玩家 |
| 破坏方块 | 可破坏（无掉落） | 可破坏（镐，掉落自身） |

所有改名与传送请求都会在**服务端**重新校验，客户端伪造的请求会被静默拒绝。

---

## 数据存储

模组使用两类世界 SavedData 持久化数据：

| 文件 | 内容 |
|------|------|
| `teleportwaypoint_waypoints` | 全局锚点索引：UID → 维度 / 坐标 / 类型 / 名称 |
| `teleportwaypoint_players` | 每名玩家的激活锚点 UID 集合 |

锚点方块实体自身还会在 NBT 中保存 `uid`、`waypoint_id`、`name`、`owner`；复制粘贴等操作导致 UID 冲突时会自动重新生成 UID。

---

## 网络同步

客户端与服务端采用“按维度 + 按激活状态”的同步策略：

- **普通传送锚点**：进入服务器或跨维度时，服务端同步**当前维度**的所有普通锚点完整数据。
- **口袋传送锚点**：只同步玩家**已激活**的口袋锚点完整数据，且完整数据也只按**当前维度**同步。
- **已激活锚点元数据**（UID / 类型 / 名称）：跨维度保留，用于传送列表。
- 跨维度时，客户端会清空旧维度完整数据，并载入新维度完整数据。
- 未激活口袋锚点不会同步给客户端，避免泄露坐标。

## 构建与开发

要求：**JDK 21**。

```bash
# 构建（Windows 使用 gradlew.bat）
./gradlew build
# 产物位于 build/libs/teleportwaypoint-0.4.0.jar

# 启动开发客户端
./gradlew runClient

# 启动开发服务端
./gradlew runServer
```

项目结构：

```
src/main/java/com/zonlong/teleportwaypoint/
├── block/            # 方块与方块实体注册、交互逻辑
├── core/             # 激活/索引管理、SavedData、传送逻辑
├── menu/             # 菜单（Menu）定义
├── network/          # 自定义 Payload 与网络处理
├── item/             # 物品与创造标签页
├── config/           # NeoForge 配置
├── datapack/         # 内置可选数据包注册
├── structure/        # 区块补锚：监听器 / 扫描器 / 放置器 / 名单筛选
├── util/             # 锚点命名（tpwp. 键前缀、id 派生）
└── client/           # 客户端状态、GUI、渲染与 Xaero 集成
```

### 测试

项目**没有 `src/test`**，也不引入测试框架。行为验证使用 NeoForge 自带的 GameTest：

```bash
./gradlew runGameTestServer     # 运行全部 GameTest 并退出
```

覆盖（20 个）：命名派生与 64 字符截断、id 合法性、屋顶/落点几何、名单标签内容与 `12 + 22 = 34` 的划分、方块实体排除、确定性、放置器写入（含水中含水标记与越界拒绝）。

> `runServer` 也是廉价的完整 codec 测试：数据包注册表在世界创建前加载，畸形 JSON 会以 DFU 错误点名文件并中止启动。

## Xaero 地图联动（可选）

安装 **Xaero's Minimap / Xaero's World Map** 后，世界地图与小地图会显示本模组的传送锚点。

- 小地图与世界地图均**严格按当前玩家所在维度隔离**：进入下界/末地后不会显示主世界锚点。
- 由于客户端只持有当前维度完整数据，**世界地图切换到其他维度时不会显示锚点**（这是当前设计行为）。
- 世界地图图标：
  - 传送锚点：未激活红色 / 已激活青色；
  - 口袋锚点：已激活绿色（未激活不显示）。
- 小地图图标：
  - 传送锚点：未激活红色 / 已激活青色；
  - 口袋锚点：未激活黄色 / 已激活绿色（未激活不显示）。
- 世界地图右键锚点可打开菜单：
  - 第一行：名字；
  - 第二行：坐标（仅展示）；
  - 第三行：传送（已激活可点击，未激活不可用）。
- 配置文件位于 `config/teleportwaypoint/`：
  - `common.toml`：通用配置（传送冷却、区块补锚名单模式与调试日志、可选数据包分组）
  - `xaero-minimap.toml`：Xaero 小地图联动配置
  - `xaero-worldmap.toml`：Xaero 世界地图联动配置
- 小地图与世界地图各自独立控制：
  - `showWaypoints`：总开关；
  - 小地图：统一 `range` 控制显示距离（0 = 不限制，默认 256 格）；
  - 传送锚点：分别控制未激活、已激活是否显示；
  - 口袋锚点：仅玩家激活后显示，未激活时不会出现在任何 Xaero 地图上。
- 未安装 Xaero 时本模组完全正常运行；Xaero 相关代码不会加载。

> 说明：配置以本模组的 NeoForge 配置为准；Xaero 设置界面中的相关选项仅作为镜像显示。

## 已知限制与后续计划

- **存量存档不会被补锚**，也没有 backfill 开关：补锚只发生在区块首次生成时（设计意图）。
- **锚点被拆除后不会重生**：拆除不改变区块的生成状态。
- 主区块已存在、结构只向**新生成**的相邻区块延伸的极少数情形会被漏掉。
- 结构内一个合格位置都没有的结构（例如开阔水下的部分结构）**永远**不会有锚点。
- 每个区块最多处理 2 个结构，每个结构最多放 1 个锚点；单个结构的探测预算为 2000 次位置判定，超限即放弃。
- 升级到 0.4.0 后，**既有存档需手动关闭**两个内置结构数据包，否则新生成区块会出现双份锚点。
- 旧的两个 NBT 覆盖数据包予以保留（默认关闭），仅作为旧存档的过渡手段；「数据包处理器精修层」未在本版本实现。
- 口袋锚点破坏后掉落的物品不会保留原锚点数据，这是当前设计行为。
- Xaero 小地图的全局名称字号会跟随距离文本字号同步，属于当前设计行为。
- Xaero 世界地图切换到其他维度时不显示锚点，因为客户端只持有当前维度完整数据。
